# Neon PostgreSQL Compute Hours Optimization & Auto-Sleep Plan

নিওন পোস্টগ্রেসের ১০০ ঘণ্টার মাসিক ফ্রি কোটার মধ্যে মাত্র ১৪ দিনেই ৮৪ কম্পিউট আওয়ার খরচ হয়ে যাওয়ার মূল কারণ চিহ্নিত করা হয়েছে এবং বাকি ১৬ ঘণ্টা দিয়ে পুরো মাস সাইট নির্বিঘ্নে সচল রাখার জন্য স্বয়ংক্রিয় কানেকশন ক্লোজ ও স্লিপ অপ্টিমাইজেশন প্ল্যান তৈরি করা হলো।

### User Review & Critical Decisions

> [!IMPORTANT]
> ব্যবহারকারীর সাথে আলোচনা ও সিদ্ধান্তের প্রেক্ষিতে নিম্নলিখিত কনফিগারেশন চূড়ান্ত করা হয়েছে:

- **Confirmed Decision 1 (Ping Monitor Impact)**: ব্যবহারকারী নিশ্চিত করেছেন যে রেন্ডার (Render) ওয়েব সার্ভিস চালু রাখতে **UptimeRobot** বা অটো পিং সার্ভিস সক্রিয় রয়েছে। এই পিংগুলোর প্রতিটি রিকোয়েস্টে ব্যাকএন্ডে `SELECT 1;` এক্সিকিউট হওয়ার কারণে নিওন ডেটাবেস ২৪ ঘণ্টা সজাগ থাকতো এবং কখনো স্লিপ (Suspend) মোডে যেতে পারতো না।
- **Confirmed Decision 2 (Architectural Strategy)**: ব্যবহারকারী **"কোডে কানেকশন অটো ক্লোজ ও স্লিপ অপটিমাইজ করা"** নির্বাচন করেছেন। ফলে রেন্ডার অ্যাপ UptimeRobot এর মাধ্যমে সজাগ থাকলেও নিওন পোস্টগ্রেস ডেটাবেস কেবল আসল ডেটা রিড/রাইটের সময়ই ১-২ সেকেন্ডের জন্য জাগবে এবং কাজ শেষ হলেই স্বয়ংক্রিয়ভাবে স্লিপে চলে যাবে।

### 1. Overview & Core Concept

- **What It Does**: 
  1. রেন্ডারের কিপ-অ্যালাইভ/হেলথ-চেক এন্ডপয়েন্ট (`/api/health`, `/health`, `/ping`) থেকে সরাসরি নিওন ডেটাবেসের `SELECT 1;` কোয়েরি সম্পূর্ণ বিচ্ছিন্ন করা হবে। ফলে UptimeRobot যত ঘন ঘনই পিং করুক, নিওন ডেটাবেস অকারণে জাগবে না।
  2. ডেটাবেস কানেকশন পুলে (`pg.Pool`) অ্যাগ্রেসিভ `idleTimeoutMillis: 1000` (১ সেকেন্ড) এবং `max: 3` সংযোগ সেট করা হবে, যাতে কোনো কোয়েরি শেষ হওয়ার ১ সেকেন্ডের মধ্যে কানেকশন বন্ধ হয়ে যায়।
  3. নিওনের সার্ভারলেস অটো-সাসপেন্ড (Auto-suspend) সক্রিয় থাকবে। দিনে যদি মাত্র ৩০ মিনিট প্রকৃত ব্যবহার হয়, তবে দিনে মাত্র ০.৫ কম্পিউট আওয়ার খরচ হবে। অবশিষ্ট ১৬ ঘণ্টার কোটা দিয়েই বাকি ১৬ দিন নিশ্চিন্তে চলবে।
  4. মেস ইআরপির ইন-মেমোরি ক্যাশ শিল্ডকে আরও নিখুঁত করা হবে যাতে স্বাভাবিক ব্রাউজিং বা রিমাইন্ডার ব্যাকগ্রাউন্ড চেক নিওনকে অযথা না জাগায়।
- **Target Audience / Persona**: মেস ফাউন্ডার এবং অ্যাডমিনিস্ট্রেটর, যারা সীমিত ফ্রি ক্লাউড রিসোর্সে সর্বোচ্চ নির্ভরযোগ্যতায় মেস ম্যানেজমেন্ট সফটওয়্যার পরিচালনা করছেন।
- **Key Value**: জিরো-কস্ট ক্লাউড অপারেশন বজায় রাখা, ডেটাবেস লিমিট এক্সহস্ট হওয়া প্রতিরোধ এবং নিরবচ্ছিন্ন সার্ভিস বজায় রাখা।

### 2. User Experience & Visual Design

- **Founder Console Neon Health Widget**:
  - ফাউন্ডার কনসোলের "Database & System Status" সেকশনে নিওন অপ্টিমাইজেশন স্ট্যাটাস কার্ড যুক্ত হবে।
  - কার্ডে প্রদর্শিত হবে: 
    - `Compute Optimization`: Active (Auto-Sleep Enabled)
    - `Ping Decoupling`: Armed (Health checks do not wake database)
    - `Connection Idle Timeout`: 1000ms (Auto-terminating idle sockets)
    - `Emergency Connection String Input`: যদি কখনো ১৬ ঘণ্টার কোটা শেষ হয়ে যায়, ফাউন্ডার যেন ড্যাশবোর্ড থেকে ১ ক্লিকে আরেকটি নতুন নিওন বা অলটারনেট ডেটাবেস ইউআরএল পেস্ট করে রিলোড দিতে পারেন।
- **Interactive Feedback**:
  - টেস্ট পিং বা ডেটাবেস হেলথ টেস্ট বাটনে ক্লিক করলে লাইটওয়েট পিং টেস্ট হবে এবং কনসোলে স্পষ্ট নোটিফিকেশন আসবে: "Database is in safe low-compute mode."

### 3. Key Product Decisions & Trade-Offs

- **Decision 1: Decoupling Keepalive Pings from Neon SQL Engine**
  - *Chosen Approach*: `/health` এবং `/api/health` এন্ডপয়েন্টগুলো মেমোরি ও প্রসেস আপটাইম থেকে তাৎক্ষণিক 200 OK রেসপন্স দেবে, নিওনে `SELECT 1;` পাঠাবে না।
  - *Why*: UptimeRobot প্রতি ৫ মিনিটে পিং পাঠালেও রেন্ডার সার্ভার ১০০% জেগে থাকবে, কিন্তু নিওন প্রতি ঘণ্টার ৫৫ মিনিটই ডিপ স্লিপে থাকবে। এতে ২৪ ঘণ্টায় নিওন কম্পিউট খরচ নেমে আসবে মাত্র ১-২ ঘণ্টায়।
  - *Alternative Considered*: UptimeRobot বন্ধ করে দেওয়া। (বাতিল: রেন্ডার ফ্রি টিয়ারে ১৫ মিনিট পর পুরো সার্ভার স্লিপে চলে যায়, ফলে ব্যবহারকারীর ওয়েবসাইট খুলতে ৫০ সেকেন্ড লোডিং বিলম্ব হতো)।

- **Decision 2: Connection Pool Idle Auto-Termination**
  - *Chosen Approach*: `pg.Pool` এ `idleTimeoutMillis: 1000` (১ সেকেন্ড), `max: 3`, এবং `allowExitOnIdle: true` কনফিগারেশন প্রয়োগ।
  - *Why*: নিওনের সার্ভারলেস আর্কিটেকচার কেবল তখনই কম্পিউট সাসপেন্ড করে যখন ওপেন টিসিপি কানেকশন সংখ্যা ০ হয়। ডিফল্ট পুলে কানেকশন ১০ সেকেন্ড বা তার বেশি সময় ধরে খোলা থাকত, যা সাসপেনশন আটকে রাখতো।

- **Decision 3: Zero-Data-Loss Multi-Tenant Integrity**
  - *Chosen Approach*: প্রতিটি মেসের জন্য ইন-মেমোরি ক্যাশ এবং লোকাল ফাইল ব্যাকআপ সবসময় সক্রিয় থাকবে। কোনো ইউজার কোনো পরিবর্তন করলে (যেমন মিল বা বাজার এন্ট্রি) তা সঙ্গে সঙ্গে নিওনে সেভ হবে এবং সাথে সাথেই কানেকশন ক্লোজ হবে।

### 4. Technical Architecture & Data Strategy

```
┌─────────────────────────────────────────────────────────────┐
│                 UptimeRobot / Auto-Ping                     │
└──────────────────────────────┬──────────────────────────────┘
                               │ (Pings every 1-5 mins)
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                 Render Express Backend Web Service          │
│                                                             │
│  ┌──────────────────────┐      ┌─────────────────────────┐  │
│  │ /api/health Endpoint │ ───► │ Instant HTTP 200 (OK)   │  │
│  │ (Zero DB Query)      │      │ (No Postgres query run!)│  │
│  └──────────────────────┘      └─────────────────────────┘  │
│                                                             │
│  ┌──────────────────────┐      ┌─────────────────────────┐  │
│  │ User Action / Write  │ ───► │ Acquire Pool Client     │  │
│  │ (Save Meal / Bazar)  │      │ Execute Postgres Query  │  │
│  └──────────────────────┘      │ Auto-Release Socket     │  │
│                                └────────────┬────────────┘  │
└─────────────────────────────────────────────┼───────────────┘
                                              │ (Idle > 1s -> Sockets close)
                                              ▼
                                 ┌─────────────────────────┐
                                 │ Neon Serverless Compute │
                                 │  [AUTO-SUSPEND ACTIVE]  │
                                 │  (Zero Compute Used     │
                                 │   When No Active Users) │
                                 └─────────────────────────┘
```

#### Key Implementation Changes:
1. **`server.ts`**:
   - `keepAlivePaths` হ্যান্ডলারে `pool.query("SELECT 1;")` এবং `SELECT version();` রিমুভ করা হবে।
   - হেলথ চেক শুধুমাত্র সার্ভার আপটাইম, মেমোরি স্ট্যাটাস ও ক্যাশ স্টেট প্রদান করবে।
2. **`src/db/index.ts`**:
   - `createPool()` ফাংশনে `idleTimeoutMillis: 1000`, `max: 3`, `connectionTimeoutMillis: 10000`, `allowExitOnIdle: true` কনফিগার করা হবে।
   - নিওন কানেকশন স্ট্রিং পুলে হ্যান্ডেল করার জন্য সুরক্ষিত অপটিমাইজেশন।
3. **`server/db.ts` & `server/routes.ts`**:
   - ব্যাকগ্রাউন্ড সিনক্রোনাইজেশনে অপ্রয়োজনীয় লুপ এবং অনবরত কোয়েরি রান নিয়ন্ত্রণ করা হবে।
4. **`src/components/FounderConsole.tsx`**:
   - নিওন রিসোর্স সেভার ব্যাজ ও ডায়াগনস্টিক তথ্য প্রদর্শন।
